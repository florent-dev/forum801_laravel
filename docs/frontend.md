# Front end

## Layout

`resources/views/components/layouts/app.blade.php` holds:

- the header: logo, search trigger, tour button, community switcher, and either `HeaderBar` or the guest buttons;
- the account banner (`partials/account-banner`): unconfirmed email, mute or suspension;
- the two panels: the `left` slot and the main slot;
- the global components: auth modal (guests), sanction modal and IP modal (staff), search modal, tours, confirm dialog, lightbox, toasts;
- the inline Alpine setup, then `@livewireScripts` and `public/js/forum-nav.js`.

Scripts in the layout use `data-navigate-once`, so they run only once with `wire:navigate`.

## CSS

One file: `public/css/forum.css`. The palette comes from the original forum and lives in `:root`:

| Token | Use |
|---|---|
| `--bg` `#0e242d` | Page background, inputs |
| `--area` `#1c3c41` | Panels, modals |
| `--item` `#274850`, `--item-hover` `#3a6c77` | List items |
| `--sticky` `#18243a` | Pinned items, side boxes |
| `--accent` `#009d9d` | Links, primary buttons |
| `--accent-2` `#2ecf73` | Success, "never opened" counters |
| `--warn` `#babd2f` | Yellow counters, guild accents, moderation |
| `--danger` `#eb1d51` | Errors, destructive actions |

Rules of thumb: no text below 11px; reuse `.btn`, `.chip`, `.pill`, `.ui-content`, `.form-box`, `.settings-card`, `.modal`; the mobile layout is the `@media (max-width: 800px)` blocks. The stylesheet URL carries its `filemtime`, so browsers reload it after every change.

## Icons

| Kind | Where | Use |
|---|---|---|
| Illustrated icons | `public/img/icons/*.svg`, `<x-art name="…" size="20" />` | Navigation, menus, headings. Same style as the section icons: dark-brown outline, warm flat colors, soft highlight |
| Line icons | `<x-icon name="…" />` (inline SVG) | Editor toolbar and small UI controls |

The illustrated icons are generated by `resources/icons/generate.py`. To add or tweak one, edit the `ICONS` dictionary and run `python3 resources/icons/generate.py`, so all icons keep the same outline and highlight rules.

## Alpine helpers (defined in the layout)

| Helper | Usage |
|---|---|
| `x-modal` component | `<x-modal name="foo" :title="__('…')">…</x-modal>`, opened with `$dispatch('open-modal', 'foo')` or `$this->dispatch('open-modal', name: 'foo')` |
| `$confirm` | `$confirm(message, () => $wire.action(), { title, label, danger })`. Use it instead of `wire:confirm` |
| Toasts | `$this->dispatch('toast', message: __('…'), type: 'success|info|error')`; `session()->flash('toast', …)` before a redirect |
| Lightbox | Automatic for images inside `.post-body` |
| `draft(key)` | Keeps an unsent textarea in `localStorage` (`<x-editor draft="…">`) |
| `forumTour(steps, done, url, key)` | Per-page guided tours (`partials/tour.blade.php`) |

Scrolling: only panels (`.scroll`) scroll; the page body is fixed. Use `window.scrollInPanel(el, 'start'|'center', smooth)` instead of `scrollIntoView()`, which would also move the body and shift the layout.

Dimming: never put `opacity` on a whole `.thread-post`. It creates a stacking context that fades the author menu and traps it under the next post. Dim `.post-body` and the avatar instead.

Alpine expressions cannot contain statements such as `try {}`. Put any logic like that in `Alpine.data()` or `window` helpers.

## `public/js/forum-nav.js`

- Keeps the left list scroll position across `wire:navigate` (keyed by `data-section`).
- Scrolls to the reported or targeted post, the "new messages" divider, or the bottom of a fully read thread.
- @mention autocomplete for textareas, `[data-mention-input]` and `[data-mention-multi]`.

## Livewire patterns

- Ids that the client must not change are `#[Locked]` (`threadId`, `ceilingId`, `highlightPostId`, …).
- Re-authorize in `render()` and in every action; never trust `mount()` alone.
- Find nested records through their parent (`Post::where('thread_id', $this->threadId)->findOrFail($id)`) so foreign ids are rejected.
- Pagination views: `partials/pager` (Livewire) and `partials/pager-links` (plain links).
