# Languages and communities

## Interface language and community are separate

| | Interface language | Community |
|---|---|---|
| What it changes | Every UI string, dates, emails | Which sections the home page, latest activity and search show |
| Stored | `users.locale` for members, session for guests | Session only, never on the account |
| Default | Browser `Accept-Language` (`Support\Locale::fromRequest`) | Browser language mapped to a community (`Support\Community::fromRequest`, `pt` → `br`) |
| Changed with | 🌐 menu in the header, Settings › Language | Flag menu in the header |
| Config | `config/forum.php` → `locales` | `config/forum.php` → `communities` |

`SetLocale` applies `Locale::current()`: account setting, then session, then browser. New accounts get the language they were browsing in. Each section belongs to one community. Guild forums are listed separately, whatever the community.

### Adding a community

1. Add an entry to `config/forum.php` → `communities` (`label`, `flag`) and put the flag image in `public/img/flags/`.
2. To offer a new interface language as well, add it to `locales`, run `php artisan lang:add <locale>` (laravel-lang), create `lang/<locale>.json` and add the locale to the dataset in `tests/Feature/TranslationsTest.php`.
3. Create its sections in the admin page (or in `SectionSeeder`).

## Translating strings

- UI strings use English keys: `__('Mark all as read')`, `trans_choice(':count post|:count posts', $n)`.
- Keys with parameters use `:name` placeholders. Never build sentences by concatenating words.
- Notifications store `key` + `params` and are translated when **displayed**, in the reader's language (`ForumActivity`).
- Do not translate user content, nicknames, section names or role labels from the database.

`tests/Feature/TranslationsTest.php` fails as soon as a key used in the code is missing from any community language, or a translation loses a placeholder. It finds:

- literal keys in `__()`, `trans_choice()` and `@lang()`;
- notification keys passed to `ForumActivity` from `app/Services` (strings containing `:actor`, `:guild`, `:reason`, `:title`, `:subject` or `:role`);
- labels translated dynamically (`__($label)`), listed in the test itself.

When you add a dynamic label (a prefix, a sort, a duration…), add it to that list too.

To find keys that are missing in a language by hand, extract every literal key from `app/` and `resources/views/` (`__()`, `trans_choice()`, `@lang()`) and compare the list with `lang/<locale>.json`. Framework strings (validation, auth, pagination) come from `laravel-lang` (`lang/<locale>/*.php`).
